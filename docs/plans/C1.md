# C1 + the herd: build plan

Sources: dev-plan C1/C3, picks.md (C1 Look A bookcase, one room cap), mockup
design/mockups/screens/pets-shelves.html look A (near / full / later / a shelf opened).

## The idea in one breath

Pets split into **cards** (full Pet records) and **the herd** (plain pets folded into a count per
rarity x finish). Cards: favourites, the active pet, holo or better, a pet that brought a part new
to the book, pets with buttons (F2, a hook only), good pulls still pinned, pets away on a trip or
leading a party, and the newest 20 plain pets of each rarity. When a 21st plain pet lands on a
shelf, the oldest free plain card folds into the count. Jobs and workers hold counts. Adventures
(parties of at most 10) use **stand-ins**: a throwaway Pet made from a herd count (a look rolled
from a seed, the rarity's average stats, no traits, uid `h:<rarity>:<finish>:<n>`), so Party,
RunState, the trail and the postcard don't change.

## Collection

- `pets` = cards only (pull order). `herd := {}` "rarity:finish" -> count. `count()`,
  `count_of(rarity)`, `shiny_of(rarity)`, `plain_count()` (herd + plain cards) kept as running
  totals (O(1)); `_plain_cards := {}` rarity -> uids in pull order for folding.
- `always_card(pet)`: fav, active, finish rank >= card_from, new_part, buttons (F2 later).
  GameState adds its own "busy" check (pinned, away, party leader) through a callable, so the
  collection stays plain data.
- `add()`: counts the book as today, marks `new_part` when a part is seen for the first time,
  then `_fold(rarity)`: while a shelf has more than keep_cards plain cards, the oldest foldable one
  becomes a count; emits `pets_folded(uids, keys)` so GameState moves its job / worker place to
  the crew's count.
- `add_plain(key, n)` (fast path, debug and tests; no book counting).
- `set_fav(uid, on)`; unfaving or a new active pet re-runs `_fold` for that shelf.
- `get_pet("h:...")` returns the cached stand-in; `remove()` of an `h:` uid takes one from the
  herd count. Every pet that leaves adds a star.
- `fallen` becomes a list of palettes (at most fallen_keep) + `fallen_n` (all stars ever).

## GameState

- Jobs: `jobs[id] = { crew: [card uids], herd: { key: n }, fill }`. New `job_size(id)`,
  `job_faces(id, n) -> Array[Pet]` (cards, then stand-ins, for polaroids and piles). `job_rate`
  / `job_tips` sum cards + counts x the bucket's speed / tip. `put_on_job(count)` and
  `take_off_job(count)` pick best / slowest across cards and whole buckets. `share_out` and
  `_auto_place` spread counts too. `Jobs.work` gets `job_size`.
- Workers (machines, tables): `automation.wherd[id] = { key: n }` next to the uid lists;
  `workers_count` / `workers_speed` include it. Adventure party leaders stay uid slots; a herd
  leader is a stand-in uid there.
- Resting: `resting_cards()`, `resting_herd() -> { key: n }`, `resting_count()` (herd minus
  what's on jobs, working, or away as stand-ins; cached, redone when crews, workers or runs
  change). `resting_pets()` goes away. `sendable_pets()` = free cards + up to 10 stand-ins per
  resting bucket (kept stable between calls), so the party picker and quick picks work as now.
  `send_on_adventure` checks by uid. `collect_run`: stand-ins home just stop counting as away;
  lost ones leave the herd (stars).
- Room: save field `room` (level). `room_cap()`, `room_left()`, `buy_room()`. `open_boxes`
  opens only while `room_left() > 0` (count clamped to it; a box never half-opens) and emits
  `room_full` otherwise; covers hand, your pet, box workers and the machine's pet box. Gifts
  (tutorial pets, found pets) always come in. Nothing is lost: boxes stay on the pile.
- `collection.pets.size()` uses (tutorial, pet box odds, machine tab, boxes tab) -> `count()`.

## Save: v22 -> v23 (bump once)

`collection`: `{ pets: [cards], herd: { "common:normal": n }, active, next_id, seen,
fallen: [palettes], fallen_n, stand_next }`; pet dicts may have `fav`, `new_part`. `jobs[id].herd`,
`automation.wherd`, top-level `room`.
Migration: fallen `[uid, palette]` -> palettes + fallen_n; old pets get `new_part` by walking them
in pull order (the first pet with each part). Folding runs at the end of load (after jobs,
automation, runs and pinned are loaded), so old crews of uids turn into counts on their own.
Stars move once (placed by index now); never explained.

## Night sky

Star i is placed by `hash(i)`, tinted by `fallen[i]` (or a palette picked by the hash past
fallen_keep). Draws at most room + a capped band, so a million leavers cost the same.

## UI (920x600, fits)

- Bar: `pets | toys | book` ... room pill on the right (shown once the first pet folds).
  Tap the pill: a small card under it, "more room" with 500 -> 750 and a coin button.
  Full: pill pink, wiggles every few seconds; a refused opening makes your pet say a squish
  line ("squish... can everyone breathe in a bit?").
- Cushion (pink): up to 9 minis: active (moon), favourites (heart), best cards (holo+, new part
  "new!"). Tap one = its shelf opens with it chosen.
- Bookcase: a plank per rarity you have (hidden until found): tilted tag "common 48,210", the 4
  newest standing, a mound (sprite count ~log of the count, max 60), "✦ 1,204". Tap = open.
- Opened shelf: "‹ shelves  rare  3,190", herd chips (plain pile + count, ✦ shiny + count), the
  always-cards of that rarity, a stitch line, the newest 20; the side sticker (PetDetails) with
  the heart + make active. Always-cards page past 30 (see questions).
- Tutorial target: the cushion's first mini, then make active.

## Dev steps + flow

Steps: `herd <rarity> <finish> <n>` (fast plain pets), `room <level>`, `fav <n>` (the newest n
cards become favourites), `shelf <rarity>` (opens it). Existing `pets <n>` keeps rolling real
pets (they fold as they land).
Flow `pets_shelves`: from rich, view full, herds like the mockup's near numbers -> tab
collectibles, expect fits, shot near; `shelf rare`, shot shelf; back; fill to 500, tab boxes,
click open (expect the squish line), tab collectibles, shot full; `room 12` + herd to 1,000,000
commons, shot later; expect fits each time. Re-run errands, errands_crowd, workers, automation,
party, postcard, tutorial, fits.

## Tests

- Folding: 25 plain commons -> 20 cards + 5 in the count; fav / active / holo / new part stay
  cards; unfav re-folds.
- Migration: the v22 test save (pets on jobs, workers, fallen list) loads as v23 with the same
  totals, crews as counts, fallen_n kept, save much smaller.
- Crews from counts: put_on_job 1,000 from the herd, rate and tips match the cards version,
  take off returns them; workers speed; share_out spreads counts.
- Adventures: stand-ins sent, one lost -> herd count down one, a star added, the rest back.
- Room: full -> open_boxes returns nothing and the box stays; buy_room grows the cap.
- 1M: `add_plain` 1,000,000 commons; save + load + put all on a job + the bookcase build each
  under ~100 ms, save file stays small.

## Questions for Emilia (smallest safe pick for now)

1. Holo and better are always cards, so late game there could be tens of thousands of them
   (~3% of pulls). For now the opened shelf pages them; maybe later only holo+ with something
   extra stays a card?
2. The room pill turns up when the first pet folds into the herd (21 of one rarity).
3. Room prices and growth are placeholders (500 coins, x1.8 each; room x1.5 each).
4. Herd pets work with their rarity's average stats and no traits.
5. Unfaving an old pet folds it right away if its shelf has 20 newer ones.
6. The old grid's sorts and filter chips go away (the bookcase replaces them).
7. Gifts (tutorial pets, found pets) ignore the cap; only box openings wait.
