# A1 Pacing simulator: build plan

A headless tool that plays a pretend player through the whole early game and prints when things
happen and where the coins come from. Then a short report with suggested numbers. No game code,
no data, no save, no UI changes.

## The idea: drive the real GameState, fake only the clock

machine_pace.gd copies GameState's glue (fever, capsules, bits). That drifts as soon as other lanes
change the rules. So pace.gd makes its **own GameState instance**
(`load("res://scripts/game_state.gd").new()`, never added to the tree so `_process` never runs)
and calls its real methods: `pull_lever`, `buy_machine_upgrade`, `send_on_adventure`,
`collect_run`, `put_on_job`, `buy_errand_tool`, `buy_gear`, `teach_job`, `set_task`,
`buy_auto_tool`, `teach_others`, `buy_spots`, `put_workers`, `set_auto_party`, `buy_boxes` /
`open_boxes`, `rummage`, `feed`, `follow_lead` / `follow_rumour`. Unlocks, the tutorial, job goals,
tips, the kitchen, scout notes, gear on trips, pet boxes and intel all run through the game's own code.
So after the big merge the sim can just be run again.

GameState reads `Time.get_unix_time_from_system()` directly. Without touching game_state.gd
(other lanes edit it), the sim keeps its own clock `t` (1 s ticks) and shifts timestamps:
- errands: `gs._work_for(dt)` (it takes seconds). Automation: `Automation.crank` / `Automation.work`
  + `gs._pet_cranks` (the 10 lines of `_work_for_automation`, split so pet and workers count
  apart), then `gs._auto_adventures()`.
- adventures: after a send (hand or auto), shift the run's `started` / `next_at` onto sim time;
  each tick `AdventureRunner.resolve(run, Chooser.for_run(run), T0 + t, catalog)`. Hand-sent runs
  that wait get an answer from a "sensible" pick (like balance.gd: risky while healthy, safe when
  hurt), then resolve.
- fever: before a pull set `gs.fever_until` from the sim's fever end; after a lucky pull read it back.
- rummage: the sim keeps each spot's refill time and clears `gs.rummaged[spot]` when due.
- the passive coin (1 per `COIN_INTERVAL` at full care) is added by the sim; it feeds the pet.
- saving off: `_can_save = false` and a scratch `save_path`, then `debug_new_game()` for a clean
  start (the test-sim profile's save is never written).

## The pretend player ("steady", the default)

- Pulls the lever nonstop: one pull every `LEVER_SECONDS` 0.9 + `gs.capsule_seconds()`.
- Keeps one hand-sent party out at all times (biggest party allowed), to the place that brings the
  bit the next repair needs (`finish_rewards` in adventures.json), else the best coins. Follows
  every lead and rumour. No treat tossing or trail clicks (a flag `--trail` can model treats as
  the average speed-up later; off by default).
- Every other resting pet goes on errands: coin hunt first; 1 on the jar, 1-2 cooks, 1 scout when
  those open; the rest where coins/min is best (`gs.errands_per_minute_with`).
- Spends xp on the cheapest gear upgrade it can (xp buys nothing else).
- Spends coins by **payback**: every affordable buy is scored by extra coins/min per coin
  (errand tools via `errands_per_minute_with`, crank tools / spots / boxes by pulls gained x
  `Machine.coin_value`). "Gate" buys (the next repair, the first level of a new job's tool, teach a
  job, teach the others, the first spot) always win, and the player saves for one when it's less
  than 10 minutes of income away.
- Buys starter boxes once the boxes tab is open, when a new pet pays back (more crew).
- Toys are not played (their boosts use real time); listed as a gap in the report.
- A second style `--style=casual` (lever 1 pull in 4, checks in every 5 min) for a lower bound.

## Output

`godot --headless -s tools/pace.gd -- --profile=test-sim [--minutes=240] [--runs=5] [--style=steady] [--seed=1]`

1. **Milestones**, the median minute over the runs (and how many runs got there): each repair and
   tree node, adventures open, basket / errands open, each new job (lemonade, jar, kitchen,
   scouting), better drops, boxes tab, toys, first pet box, tiny machine / automation tab, machine
   job taught, crank lv 3, teach the others, first worker, auto adventures, each gear level,
   parties 3/5/10, trips 40 / 60. Recorded from `gs.unlocked`, the tutorial step and state checks,
   in sim minutes.
2. **Every 10 minutes**: coins/min by source (lever, each errand job, adventures, your pet's
   crank, workers, rummage, passive), plus coins banked, pets, xp, bits.
3. **What's waiting**: at each gate, how long the player sat saving for it (the slow spots).

machine_pace.gd stays as it is (quick tree-only check); its header gets a line pointing to pace.gd.

## Files

- new `tools/pace.gd` (SceneTree: clock, loop, printing) and `tools/pace_player.gd` (the pretend
  player's choices), with .uid files.
- `tools/machine_pace.gd`: one comment line.
- new `docs/reports/pace.md`: plain and short. The curve in a few lines, the slow and too-fast spots,
  and SUGGESTED numbers for data/automation.json (job prices, crank / stool / grease / cutters,
  teach, spots) and anything else badly off (tree, errand tools, gear prices). Suggestions only:
  data/ is not changed.
- `docs/plans/A1-done.md`: the done-notes (text for design.md, architecture.md, the dev plan and
  CLAUDE.md).

## Data, save, UI, flows

- Data shape: none (reads every data file as it is). Save: no change, no version bump.
- UI: none. Flows: none. Dev steps: none.

## Tests

- No test_core change (keeps the lane conflict-free). Check: `--minutes=10 --runs=1` finishes in a
  few seconds and passes the tutorial; a full run finishes in under a couple of minutes.
- Run test_core and balance.gd once at the end to be sure nothing else moved.

## Build order

1. Skeleton: own GameState, no saving, clean start, the clock; check autoloads don't interfere in
   `-s` mode.
2. Lever + tree + tutorial; compare the repair minutes with machine_pace.gd (should roughly match).
3. Adventures (hand party, answers, bits, xp, leads, gear).
4. Errands (crews, tools, goals, the new jobs), boxes, rummage.
5. Automation (machine job, tools, workers, spots, auto adventures).
6. Milestones + per-source table + casual style; run; write the report.

## Questions for Emilia (my picks until then)

- How active is "a player"? Pick: nonstop lever while trips walk, no trail clicking, as the main
  run; casual as the slow bound.
- Toys left out (their boosts need real time); the report says so.
- How long is "the early game"? Pick: 4 hours of play, or until the first worker, whichever is later.
