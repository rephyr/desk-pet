# B2 boost plumbing (no receipt UI yet)

One place that answers "how much is X boosted right now, and by what?". Toys are the only shared
source in this branch; book stickers (A4), knacks (D1), the kitchen and the darker currency plug
in later as more sources. Boosts from different sources multiply. No UI, no save change.

## Files

- `data/boosts.json` (new): the kind table.
- `scripts/core/boosts.gd` (new, `class_name Boosts`): static, so tests can use it without GameState.
- `scripts/core/catalog.gd`: load `boosts.json` into `catalog.boosts`.
- `scripts/machine/toys.gd`: `Toys.parts(state, catalog, kind, now)` gives one part per working
  toy edition; `Toys.multiplier` becomes `Boosts.total(Toys.parts(...))` (same order, same
  product). `ALL_COVERS` moves to the kind table (`"all": true` on coins, xp, luck).
- `scripts/game_state.gd`: `boost(kind) -> float` and `boost_parts(kind) -> Array[Dictionary]`.
  `toy_boost` is removed and all 19 call sites (game_state, machine_tab, errands_tab) call
  `boost()` instead. Removing the old name means a lane that still calls `toy_boost` fails loudly
  at merge time instead of quietly skipping the new sources.
- `scripts/dev/dev_driver.gd`: new step `boosts`, which logs every kind with its total and parts.

## Data shape

```json
{ "_note": "...",
  "sources": ["toys", "book", "knacks", "kitchen"],
  "kinds": [
    { "id": "coins", "name": "coins", "all": true },
    { "id": "xp", "name": "xp", "all": true },
    { "id": "luck", "name": "luck", "all": true },
    { "id": "speed", "name": "capsule speed" },
    { "id": "fever", "name": "fever" },
    { "id": "toys", "name": "toy drops" },
    { "id": "loot", "name": "adventure loot" },
    { "id": "errands", "name": "errand speed" },
    { "id": "automation", "name": "worker speed" } ] }
```

`sources` sets the order for the receipt later. `name` is the receipt's word later (not shown yet).

A part is `{ "source": "toys", "id": "acorn:holo", "x": 1.14 }`.
`Boosts.total(parts)` is the product of every `x` (1.0 for none). `boost_parts` of an unknown kind
returns `[]` and a `push_error`.

## Where kinds are used

- Existing (unchanged maths): coins, xp, luck, speed, fever, toys, loot, everywhere `toy_boost`
  was used.
- New kinds with no source yet (all 1.0, so nothing changes):
  - `errands`: multiplies `job_rate()` (meters fill faster).
  - `automation`: multiplies the seconds passed to `Automation.crank` and `Automation.work`
    (pulls and boxes), and divides the "a pull every Ns" text on the automation tab.
- Gear stays out: its numbers are packed per trip (`run.gear`), and none is a shared kind. The tote
  still multiplies trip coins inside `_boost_trip_loot` next to `boost("loot") * boost("coins")`.
  Gear luck is added to the trip's success chance, not multiplied. Later that could be a "why so
  much?" tape inside adventures.
- The kitchen isn't on this branch (it came in 9712be2 after this lane's base). Merge note: it
  becomes source `kitchen` of kind `errands` with `x = 1 + kitchen_bonus()`, multiplied onto
  `job_rate` rather than added to the tools' speed. The numbers change a little, so check the
  balance diff when merging.

## Tests (tests/test_core.gd, `_test_boosts`)

- Every toy `bonus` is a kind in the table, or `all`. Every kind has an id and a name.
- No toys: every kind's parts are `[]` and the total is 1.0.
- Two coins toys plus one `all` toy playing: coins has 3 parts, luck has 1 (the `all` toy), speed
  has 0. The total equals the product of `Toys.boost` for each edition, which is the old
  `Toys.multiplier` value.
- A favourite counts without playing. A play that has run out doesn't count.
- Sources multiply: toy parts plus a fake `{source: "book", x: 1.5}` part gives the toys' total
  x 1.5.
- An unknown kind gives `[]` and 1.0.
- Balance: `tools/balance.gd` output is the same before and after (diff it).
