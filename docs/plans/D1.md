# D1 knacks (look C: sewn badges)

Every part has a named knack (35, the table in design/mockups/screens/knacks.html). Its size is
the kind's step x the part's rarity x the pet's finish. Your ACTIVE pet's knacks are a boost source
(`knacks`) in the B2 plumbing; other pets' knacks help a little on their own trips and jobs.
Traits stay as they are. No saved state: knacks come from parts + finish.

## Data: data/knacks.json (new)

```json
{ "_note": "...",
  "opens": "feature:parts",
  "rarity_x": { "common": 1, "uncommon": 2, "rare": 3, "epic": 5, "legendary": 8, "mythic": 12 },
  "finish_x": { "normal": 1, "shiny": 1.25, "holo": 1.5, "ghost": 1.75, "glitch": 2, "prismatic": 2.5 },
  "own": 0.25,
  "kinds": {
    "coins": { "step": 5, "text": "+{n}% coins", "icon": "knack_coins" },
    "fever": { "step": 6, "text": "fever {n}% longer", "icon": "knack_fever", "opens": "machine:fever" },
    "power": { "step": 5, "text": "+{n}% power", "icon": "knack_power" },
    ... },
  "parts": { "body:blob": { "name": "squishy", "kind": "tough" }, "body:cat": { "name": "lucky paws", "kind": "luck" },
    ..., "accessory:none": {} } }
```

- Knack kind ids = boost kind ids (no mapping). "all" (the hum) counts for every kind with
  `"all": true` (coins, xp, luck), like an "all" toy.
- Mockup kinds renamed to boost ids: capsule -> `speed`, workers -> `automation`, hurt -> `tough`,
  boxes -> `pet_boxes`.
- Size n (a %) = step x rarity_x[part rarity] x finish_x[pet finish]; x = 1 + n/100.
- A knack shows (and counts) only when: the whole system is open (`opens`, feature:parts), its kind
  is in data/boosts.json (so `power` stays hidden until fights add the kind), and its kind's own
  `opens` is open. Gates: `adventures` (tutorial past the machine), `machine:<node>` (that tree node
  fixed), anything else goes through `GameState.is_open` (feature:, tab:, location:).
- data/boosts.json gets the new kinds (only knacks feed them for now): `spots`, `trip`, `tough`,
  `safe`, `finds`, `pickups`, `treats`, `away`, `rummage`, `shiny`, `pet_boxes`.

## Code

- `scripts/pets/knacks.gd` (new, `class_name Knacks`, static like Toys):
  `of(catalog, pet, open)` (visible knacks: slot, part, name, kind, tier, n, x), `best(...)`,
  `parts(catalog, pet, kind, open)` (boost parts: one per kind, same kind adds up as in the mockup,
  id like `body:bunny+eyes:cyclops`), `own(catalog, pet, kind, open)` (1 + own x n/100),
  `party(catalog, pets, kinds, open)` (party average of `own`).
- `scripts/core/catalog.gd`: load `catalog.knacks`.
- `scripts/game_state.gd`:
  - `knack_open(kind)`; `boost_parts` appends `Knacks.parts(catalog, collection.active(), kind, knack_open)`.
  - `_boosts_changed()` also on active_changed, pet_changed (grafts), unlocked, machine_upgraded,
    tutorial_changed.
  - Other pets: `_speed_of` x `Knacks.own(pet, "errands")`; `workers_speed` x `own(pet, "automation")`.
  - Trips: `send_on_adventure` packs `run.knacks` (like gear) = boost(kind) x party average for
    trip, tough, safe, spots, finds, pickups, treats; `loot` = party share only (the active pet's
    loot stays live in `_boost_trip_loot`). Used in `treat_zoom`, trail pickups, `Intel.roll`
    (lead chance x spots), and the runner.
  - New kinds' spots: `away` (errands' and the crank's time away, the old coin trickle),
    `rummage` (rummage coins), `shiny` (pull_lever + job_boost shiny chance), `pet_boxes`
    (pet_box chance, not the sure-within-10 net). Existing kinds (coins, xp, luck, speed, fever,
    toys, loot, errands, automation) already go through boost().
- `scripts/adventure/adventure_runner.gd` / `run_state.gd`: `start(..., knacks := {})`,
  `RunState.knacks` (saved in the run dict, default {} so old runs load as x1). walk =
  1 - (1 - gear walk) / trip; hurt/injured counts / tough, lost counts / safe; bits chance + finds - 1.
  Duration preview and `estimate_return` take the knacks too.
- `scripts/adventure/intel.gd`: `roll(..., x := 1.0)` multiplies each lead's chance.

## UI (look C)

- `scripts/ui/knack_badge.gd` (new `KnackBadge`, 32 px): round sewn badge, tinted fill + 3 px
  border in the part's tier colour, dashed inner ring, the kind's doodle icon; chosen = tilted,
  a bit bigger, pink ring. Emits pressed.
- `PetDetails`: a centred row of badges under the rarity/finish tags, then a small read card for
  the chosen one (knack name, "+15% coins", muted "eyes: sparkle"). Best badge chosen first. No
  visible knacks = no row, no card. Parts, traits, stats stay (it scrolls already).
- `PetCard`: `knack := false` param; the collection grid passes true and `_draw` puts the best
  badge (24 px, tilted 10 degrees) on the top-right corner. Box reveal cards stay plain.
- `UiTheme.DOODLES`: `knack_<kind>` icons from the mockup's paths (pixel style falls back to doodles).

## Tests (tests/test_core.gd `_test_knacks`)

- Every part in parts.json has an entry; every kind has step/text/icon; every used kind is a boost
  kind, "all" or `power`.
- Sizes: common blob tough = 3, legendary x-eyes = 24, holo x1.5; "all" feeds coins/xp/luck.
- Two same-kind knacks = one part adding up; closed system / closed kind / power = no part, not shown.
- `own` is 25% of the size; party average; boost() with an active pet goes up and back down when
  the active pet changes.
