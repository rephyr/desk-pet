# X4 Tests: build plan

Tests only. Everything goes in `tests/test_core.gd`; game code changes only for real bugs the
tests find (small fixes; bigger ones listed as problems in X4-done.md).

## How the tests reach GameState

Today's tests never touch GameState (it's an autoload that loads and saves). The new ones need it
(migrations, offline catch-up, auto parties, workers), so:

- `_state_from(data: Dictionary) -> Node`: writes `data` to `DevProfile.path("save.json")` (deletes
  the `.bak` first so it can't fall back to an old one), then `load("res://scripts/game_state.gd").new()`
  (its `_init` loads the save). Checked it works headless: about 150 ms, no tree needed.
- Only with a profile: if `DevProfile.active()` is false, the GameState tests are skipped with a
  printed line (they must never read or write Emilia's real save). The lane command passes
  `--profile=test-x4`.
- `saved_at` = now, so no offline catch-up unless a test wants it. Each state is `free()`d; the
  profile save is deleted at the end.
- `_old_save(version)`: a save dict built in code, shaped like that version wrote it (no new
  fixture files).

## Tests (new functions, called from `_init`)

1. `_test_migrations`
   - A v21 save with 30 pets, automation (machine + adventures taught, crank 3, stool 1, task,
     party, others, spots, workers incl. an empty party slot "", parties, wfill), errand crews and
     tools, an auto run (slot 0), bits, machine, toys, unlocks. Loads with: gear `{}`, scout_notes 0,
     every automation field, worker, crew, run (auto, slot, chooser) and unlock still there.
   - The same save marked v22 loads the same (v23 only added scout_notes).
   - Round trip: load, `save_game()`, load again: same data (saved_at aside), version =
     SAVE_VERSION. Loading twice changes nothing.
   - v14 save with `feature:packs` + packs_on: moves to the automation boxes task (and off: taught,
     no task). v13/v18/v19 spot checks stay green.
   - A save from a newer version: loads, but `save_game()` doesn't write over it.
   - Bad data cleaned: scout_notes 99 clamps to the hold, unknown gear dropped, a worker who's
     gone / the active pet / on an errand / in two jobs / past the spot count is dropped.
2. `_test_crank_catch_up`
   - Load a save closed 2 h ago, task machine: no stool, nothing cranked (idle log empty, fill
     unchanged); stool lv 1, one hour of pulls (fill + idle log coins match
     `Automation.crank` for 3600 s).
   - Machine workers also crank while away, only as long as the stool lets them.
   - A long away (stool 8, crank 20, 500 machine workers: thousands of pulls, past
     PET_CRANK_ROLLS): loads in under 2 s, coins grow about in proportion to pulls.
   - The computer slept (`_work_automation` gap > 5 s): no stool counts at most 60 s.
3. `_test_auto_adventures`
   - adventures taught, task adventures: `_work_automation(now)` sends a party (auto, slot -1,
     chooser "policy", size = `auto_party().n`); pinned (unseen) pets, workers and the active pet
     stay home; no scout note taken; gear packed.
   - Policy never waits: over every place's events, `PolicyChooser` takes the default option and
     a policy run resolved to INF ends DONE without ever WAITING.
   - A done auto run is collected quietly: trips_done +1, idle log "trips", run gone, a new party
     goes out; a pet lost -> an announcement. Tutorial on -> nothing sent. A party set to a closed
     place falls back to an open one (not a solo dungeon).
4. `_test_many_workers`
   - 5000 pets; machine, boxes and adventures taught to the others; 2000 machines, 1000 tables,
     200 parties. `put_workers(-1)` fills them fastest first, nobody in two jobs, never the active
     pet or an errand pet; `workers_speed` = the sum of `worker_speed`.
   - Time budgets (generous, headless): putting on 2000 < 0.5 s, an hour of
     `_work_for_automation` < 0.5 s, sending 200 parties in one `_auto_adventures` < 1.5 s,
     save + load with them all < 2 s and keeps them.
   - Box workers open only what's in the pile, never buy. `take_off_workers("adventures", n)`
     leaves "" slots; a lost pet frees its spot.
5. `_test_gear_state` (A2 through GameState)
   - `buy_gear` spends xp, levels up, refuses when short / at max / not shown yet.
   - A trip you send and an auto party both pack `Gear.for_trip`; dungeons pack none.
   - Gear survives save + load.
6. `_test_jobs_state` (A3 through GameState)
   - Kitchen: `_work_for` feeds your pet only up to meal_upto; the kitchen speeds the other jobs
     (`job_rate`), not itself.
   - Scouting: notes fill to `scout_hold()` then the job waits; the map case holds more; a trip
     you send takes one, an auto party doesn't; notes survive save + load.
   - Savings jar: one full meter pays one chunk (capsules x coin value).
   - `share_out` never puts pets in the kitchen or scouting.
   - The chain opens through job levels: lemonade lv 10 -> jar, coin hunt 25 -> kitchen,
     jar 10 -> scouting (`check_unlocks`).

Numbers in the checks come from data (catalog), not hard-coded, where they're tuning.
