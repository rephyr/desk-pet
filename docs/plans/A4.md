# A4 Book page rewards: build plan

Filling a page of the collection book opens its reward sticker: a small boost that stays for good.
Four kinds (coins, luck, automation, errands) over the 6 pages from book.html. Stickers from
different pages multiply with each other and with toys (toys x1.25 x book x1.10 = x1.375).
Numbers are placeholders until balance.

## The 6 stickers (data/book.json)

| page | sticker | kind | x | reads |
|---|---|---|---|---|
| bodies | a cozy blanket | automation | 1.10 | automation 10% faster |
| palettes | a paint set | coins | 1.10 | +10% coins |
| patterns | a roll of washi tape | errands | 1.10 | errands 10% faster |
| eyes | a magnifying glass | luck | 1.10 | +10% luck |
| accessories | a little wardrobe | errands | 1.10 | errands 10% faster |
| finishes | a glitter jar | coins | 1.10 | +10% coins |

Names kept from book.html where they fit. Patterns lost "sticky paws" (a gear upgrade now), so it
gets a new object: washi tape. Two coins pages together = x1.21, two errands pages = x1.21.

**Which page is "finishes":** the game's book has one finishes page per body (7), book.html has
one. The sticker sits on the first one (blob finishes, the page the "finishes" bookmark opens)
and opens when that page is full. The other bodies' finish pages have no sticker (see questions).

Data shape:
```json
{ "_note": "...",
  "words": { "coins": "+{p}% coins", "luck": "+{p}% luck",
             "automation": "automation {p}% faster", "errands": "errands {p}% faster" },
  "pages": [
    { "id": "bodies", "slot": "body", "name": "a cozy blanket", "kind": "automation", "x": 1.1 },
    ...
    { "id": "finishes", "finishes_of": "blob", "name": "a glitter jar", "kind": "coins", "x": 1.1 } ] }
```
The line under the name is built from `words` + x (so it can't disagree with the number).

## Where each kind goes

A new `GameState.boost(kind)` = `toy_boost(kind) x Book.multiplier(kind)`. `toy_boost` stays for
toys only (the toys view).
- **coins**: every `toy_boost("coins")` becomes `boost("coins")`: `grant()`, errands pay (578),
  `errands_per_minute`, the workers' machine (1502), `_capsule` (2035), `_boost_trip_loot`, and the
  UI lines that show coins (errands_tab 682/716, machine_tab 1012).
- **luck**: every `toy_boost("luck")` becomes `boost("luck")`: machine rolls, toy rolls, extra
  trip loot copies. Same reach as toy luck (never risky trip choices: gear owns those).
- **errands**: `job_rate` speed part becomes `(1 + tools + kitchen) x book errands`. Offline
  catch-up uses job_rate, so it counts while away too.
- **automation**: your pet's crank (`Automation.crank_seconds` / `crank` get `x := 1.0`), the
  workers (`workers_speed(id)` x book, machines and boxes), and your pet opening boxes out of sight
  (`BACKGROUND_PACK_EVERY / x`). Not auto adventures (trip time is the boots' job). The automation
  tab's "a pull every Ns" uses the same x.

Caches (`_job_tools`, `_worker_speed`) are cleared when a sticker opens.

## Building alongside other steps (merge at the end)

Several steps may be built at the same time, each on its own branch/worktree off `test`, merged
back one by one. To keep A4's merge easy:
- Only A4's files get staged (list above), never `git add -A`.
- New stuff sits in its own files (book.json, book.gd, book.flow) or in its own blocks:
  `_test_book` as one new function + one call line, dev step `book` as one new `match` branch,
  GameState book code in one section (`boost`, `book_x`, `check_book`).
- Hot spots other steps also touch: `game_state.gd` (SAVE_VERSION, to_dict/load, `toy_boost`
  call sites), `dev_driver.gd`, `test_core.gd`, `unlock_popup.gd`, `home.gd` (popup `can_show`).
  Merge rule: **SAVE_VERSION takes the next free number when merging** (A4 wants +1 over what
  `test` has then; its load needs no migration, only the new `stickers` field), both sides'
  `can_show` conditions are kept (and-ed), and both sides' boost call sites keep `boost(kind)`.
- After each merge: tests, balance, the book flow and `fits` flow again.
